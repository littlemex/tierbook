## これは何を意味していて、何を意味していないか

**意味していること。** `docs/DESIGN-cheap-quorum-and-tuning.md` の 3b・3c・3d と
`results-box-cascade-gate1.md` が引用している「この床を満たす最安はこれ」という形の推薦は、すべて点推定の
主張であって、**床を満たすことの証拠にはなっていなかった**。571 問という規模で 480 通りの方策から最良を
選べば、勝者の精度は 6.7 ポイントほど上に張り出す。これは arXiv:2608.08265 が 8 チェックポイント × 4 ベンチ
で見た形と同じで、あの論文の「11 方策の最良に同時区間を張ると下限は全条件で 0」という報告のこの project 版に
あたる。

**意味していないこと。** 方策が悪いという意味ではない。`nemotron+qwen-next -> terra` は両 run で最安の
勝者に選ばれていて、点推定は 85.3% と 87.4% である。言えないのは「85% を満たす」という**保証**の方で、
実際の精度が 85% を下回っているという主張ではない。区間は片側の言明である。

**そして再現は代わりにならない。** 上の 9 件のうち 8 件は run 2 でも同じ方策が勝っている。未保証の推薦が
二回勝つのは普通のことで、だから `Reproduction.selection` は `claims` から分けた。`failed` に混ぜると、
安定した行列が再現していないように見え、逆に `survived` に畳むと、どこでも保証されていない推薦が「再現した」
だけで通ってしまう。

## どう使うか

三つの選択肢があり、どれも正当である。

1. **床に余裕を持たせる。** 上の表が示す関係を素直に読むと、480 方策・571 問の規模では **床 + 7 ポイント**の
   点推定を要求すれば保証が出る。運用上いちばん簡単で、いちばん高い。
2. **探索を小さくする。** `max_members=3` で 480 通りになっている。2 に落とすか候補を先に絞れば K が減り、
   補正が軽くなる。ただし絞る操作自体を同じデータでやると同じ罪を犯すので、絞る根拠は別の fold から来る
   必要がある。
3. **項目を増やす。** 補正は `sqrt(n)` で縮む。571 から 2,284 に増やせば幅は半分になる。これがいちばん高い。

Bonferroni は保守的である。480 の方策は同じ 8 候補を同じ 571 問で組み替えたもので、互いに強く相関している
から、本当に必要な同時性の要求はこれより弱い。だから `adj` は達成可能な下限より低い。その方向を選んだ理由は
`simultaneous_wilson` の docstring に書いた: ここで直す欠陥は「測っていない精度で推薦が配備される」ことで、
低すぎる下限は配備を遅らせるだけだが、高すぎる下限は配備を承認してしまう。
