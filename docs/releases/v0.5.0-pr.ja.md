## 背景

最初の設計から今までの間に、リクエスト単位のルーティングは競合の多い成熟した層になった。vLLM Semantic Router 0.4.0 は signal・decision・algorithm の宣言的なパイプラインと十数種の選択アルゴリズム、費用と品質を組み合わせる `multi_factor`、replay ログ、版付きの設定契約を持つ。LiteLLM、Kong、Cloudflare、OpenRouter、Azure、Bedrock も、それぞれ費用を何らかの形で考慮してリクエスト単位に振り分けている ([調査](https://github.com/littlemex/tierbook/blob/f7a72b95d0f9392477b62359c199903c4fae9734/docs/prior-art-2026-11.md))。

一方で、利用者自身の採点済みの結果から割り当てを導き、それがどれだけ確かかを述べるものはどこにもない。価格は手書きの表、品質は公開の指標か中身の見えない分類器で、学習はプロセス内に閉じているか、人が手で反映するか、非公開である。vllm-sr 自身の `success_constrained` 提案 (2026-09-04、未実装) が欠けているものをそのまま書いている。成功確率が目標を満たす候補の中で最も安いもの、である。文献はその価値がどこにあるかも示している。ルーティングの利得の大半はタスク種別ごとの固定の割り当てで得られ (arXiv:2608.23023)、価格が変わっても意味を保つ単位は解けたタスク 1 件あたりの費用であり (arXiv:2504.13359)、選んだデータでそのまま報告した値は楽観的になる (arXiv:2510.18161、arXiv:2608.08265)。

## 方針

**tierbook はルーターであることをやめ、ルーターの横に置く面になる。** 観測から、タスク種別ごとにどの arm へ送るべきか、正解 1 件あたりいくらか、どれだけ確かかを計算し、リクエスト経路上のルーターがすでに読める設定として書き出す。設計は [`docs/DESIGN-v0.5-certification-plane.md`](https://github.com/littlemex/tierbook/blob/f7a72b95d0f9392477b62359c199903c4fae9734/docs/DESIGN-v0.5-certification-plane.md)。

| 決めたこと | 比べた選択肢 | 良い点 | 悪い点 | この形にした理由 |
|---|---|---|---|---|
| ルーターへ書き出す認証面にする | リクエスト経路上の選択器をもう 1 つ作る | どのルーターもしていないことをする。ルーターの分類・観測・デプロイをそのまま使える | ルーターの設定契約に依存し、その契約は動く | 選択器はありふれているが、認証された割り当てはない |
| 単位はタスク種別ごとの割り当て | リクエストごとの予測 | 測られた利得はここにある。ルーターは表引きとして実行できる | 種別の中の残りの利得は取らない | 独立した 3 本の研究とこのプロジェクト自身の測定で、リクエスト単位の学習はこれを超えなかった |
| 正解 1 件あたりの費用を、その日の価格で計算し直す | 観測時の請求額を使う | 価格が変わるだけで方策を導き直せ、何も測り直さなくてよい | 単価表が正確であることに依存する | 価格は測定を繰り返すべき頻度より速く動く。ゲートウェイのパッチで単価表を手書きでなく読めるようにする |
| 項目の半分で選び、残り半分で確かめる | 全項目に補正した区間を使う | 探索が何をしても成り立つ。読みやすい | 各段の標本が半分になる | 防ぎたい失敗はここで測られており (6.7 ポイントの差)、引用した文献の主題でもある |
| 認証を左右するものはすべて宣言させ、既定値を持たない | 妥当な既定値を置く | 別の研究が別の結論を表現できる。利用者の代わりに何も選ばない | 宣言ファイルが長くなる | このプロジェクトの統治原則。ロジックは注入するもので、焼き込まない |

各 verb が持つ責務は 1 文で、設計はそれを分けたまま保つ。`ingest` は写像と結合だけで、採点はしない。`derive` は区間を計算し、比べ、状態 (`certified`、`unconfirmed`、`contradicted`、`unassignable`) と fallback を決める。`export-policy` は翻訳するか、拒否する。`drift` は導き直した方策との差分、新しいトラフィックでの反証の確認、測るべきセル、どの arm にも届かなかった試行を報告する。`loop` という verb はない。ループはこれらの合成で、`examples/certification_loop/` がその 1 つである。

`predict.py` と `describe.py` は削除する。import する場所もテストもなく、案内していた install extra も存在しなかった。

## 証拠

すべて 2026-11-08 に、[`examples/certification_loop/README.md`](https://github.com/littlemex/tierbook/blob/f7a72b95d0f9392477b62359c199903c4fae9734/examples/certification_loop/README.md) のコマンドで実施した。MMLU-Pro の biology、history、math、law を、OpenAI 互換のゲートウェイ経由の 7 つの arm で測った。

| 段階 | 実行したこと | 結果 |
|---|---|---|
| derive v1 | 1,000 項目 × 5 arm で `tierbook derive` | 3 種別が `claude-sonnet-5`、history が `qwen3-next-80b`、すべて `certified`。共通の held-out 489 項目で、単一最良 arm の正解 1 件あたり費用の 0.84 倍 |
| route v1 | 書き出した設定で `vllm-sr serve`、160 件をルーター経由で送信 | Claude 系 arm に送られたリクエストはすべて 502。ルーターのログは `unknown field "cache_read_input_tokens"` を示した。`drift` は 135 件の届かなかった試行を報告 |
| derive v2 | ルーターが届く arm だけにし、`drift` が未観測と挙げた 2 arm を追加で測定 | 4 種別すべて `gpt-6.1-terra` (単一最良 arm、比 1.00) |
| route v2 | 再デプロイ、新しい 160 件 | 159 件成功、すべて `gpt-6.1-terra`。`drift`: 4 種別とも `confirmed` |
| 価格だけ変更 | 候補ファイルで `gpt-6.1-terra` の単価を 3 倍にし、何も測り直さない | `drift` が 3 種別の `gpt-5.6-terra` への移動を報告。v3 は共通の held-out 508 項目で単一最良 arm の 0.79 倍 |
| route v3 | 再デプロイ、新しい 160 件 | biology、history、law は `gpt-5.6-terra`、math は `gpt-6.1-terra` に届いた。`drift`: 2 種別 `confirmed`、2 種別 `consistent` |

この実行でコードが変わり、各変更とそれを見つけたものは記録に載せた。vllm-sr 0.4.0 が受け付ける provider の形 (`defaults.model`、backend の `provider`)。ルーターをホストの全インターフェースに公開していた listener アドレスを、既定で loopback にしたこと。32 トークンの出力上限が推論過程を誤答に変えたことから入れた `finish_reason` と打ち切り件数。502 だけの窓が空の窓と同じに読めたことから入れた、届かなかった試行の報告。ingest と drive を追記でなく置き換えにしたこと。

ゲートウェイの変更はゲートウェイを直接編集せず、パッチとして持つ: [`infra/patches/stratoclave/`](https://github.com/littlemex/tierbook/tree/f7a72b95d0f9392477b62359c199903c4fae9734/infra/patches/stratoclave)。0001 は呼び出し側が自分の請求単価とリクエストごとの費用を読めるようにする。0002 は OpenAI 互換面の Claude 応答のキャッシュ使用量を正規の形にする。`GATEWAY_REF` はそれらを当てる commit に移す。distributed-ai には変更は不要である。

記録が示していないことは記録自身に書いた。保証はタスク種別ごとで、データセットのラベルを条件とする。ルーターがリクエストを自分のタスク種別に分類したのは 159 件中 130 件と 158 件中 125 件。held-out の半分は同じ分割で 2 回確かめた。v3 の価格は検証用の仮の値。Claude 系 arm は測ったが、ルーター経由では流していない。

## テスト計画

Python 3.10 以上、Docker、`examples/certification_loop/candidates.json` の arm を提供する OpenAI 互換ゲートウェイとそのキーが必要。1 つのブロックとして貼り付ける。小さな標本 (約 840 回の呼び出し) を測り、loopback 上の vllm-sr に 40 件を流し、起動したものを片付ける。

```bash
export GATEWAY_URL=https://your-gateway.example/v1
export TIERBOOK_API_KEY=sk-your-key
export WORK=$HOME/tierbook-v050-test
rm -rf "$WORK" && mkdir -p "$WORK" && cd "$WORK"
git clone -q --branch epic/v0.5-certification-plane https://github.com/littlemex/tierbook.git
python3 -m venv venv && venv/bin/pip -q install ./tierbook pytest pyarrow 'vllm-sr==0.4.0'
(cd tierbook && ../venv/bin/python -m pytest -q)
EX=$WORK/tierbook/examples/certification_loop
curl -sL -o mmlu.parquet https://huggingface.co/datasets/TIGER-Lab/MMLU-Pro/resolve/main/data/test-00000-of-00001.parquet
venv/bin/python -I $EX/prepare_mmlu_pro.py --parquet mmlu.parquet --categories biology,history,math,law --per-category 30 --seed 1 --out items.jsonl
venv/bin/python -I $EX/prepare_mmlu_pro.py --parquet mmlu.parquet --categories biology,history,math,law --per-category 10 --seed 1 --skip 30 --out routed-items.jsonl
venv/bin/python -I $EX/drive.py direct --items items.jsonl --candidates $EX/candidates.json --base-url "$GATEWAY_URL" --out calls.jsonl --run m1 --max-tokens 1024
venv/bin/python -I $EX/grade.py --calls calls.jsonl --items items.jsonl --out outcomes.jsonl
venv/bin/tierbook ingest --calls calls.jsonl --outcomes outcomes.jsonl --out obs.jsonl
venv/bin/tierbook derive --observations obs.jsonl --candidates $EX/candidates.json --declarations $EX/declarations.json --out policy.json
venv/bin/python -c "import json,os,sys; c=json.load(open(sys.argv[1])); [v['endpoint'].update(base_url=os.environ['GATEWAY_URL']) for v in c['candidates'].values()]; json.dump(c, open('candidates-live.json','w'), indent=2)" $EX/candidates.json
venv/bin/tierbook export-policy --policy policy.json --target vsr --candidates candidates-live.json --out vsr.yaml --allow-unconfirmed --signal biology=biology --signal history=history --signal math=math --signal law=law --signal-categories biology=biology --signal-categories history=history --signal-categories math=math --signal-categories law=law --management-bind 0.0.0.0 --management-port 18080
venv/bin/vllm-sr config validate --config vsr.yaml
venv/bin/vllm-sr serve --config vsr.yaml --minimal --replace-active-config
venv/bin/python -I $EX/drive.py routed --items routed-items.jsonl --router http://127.0.0.1:8801/v1 --model tierbook/routed --out routed.jsonl --run routed-1 --max-tokens 1024
venv/bin/python -I $EX/grade.py --calls routed.jsonl --items routed-items.jsonl --out routed-outcomes.jsonl
venv/bin/tierbook ingest --calls routed.jsonl --outcomes routed-outcomes.jsonl --out routed-obs.jsonl
venv/bin/tierbook drift --observations obs.jsonl --fresh routed-obs.jsonl --deployed policy.json --candidates $EX/candidates.json --declarations $EX/declarations.json --out drift.json
venv/bin/vllm-sr stop
cd "$HOME" && docker run --rm -v "$WORK:/w" busybox sh -c 'rm -rf /w/* /w/.[!.]*' && rm -rf "$WORK"
```

確認すること: テストスイートが失敗なしの `passed` で終わる。`derive` がタスク種別ごとに状態と理由を 1 行ずつ出す (held-out が種別あたり約 15 項目なので、`unassignable` や `unconfirmed` の種別が出る。`unconfirmed` が書き出されるのは `--allow-unconfirmed` を付けているからである)。`vllm-sr config validate` が `Configuration is valid` を、`serve` が `vLLM Semantic Router is running` を出す。`drift` が certified の種別ごとに `check` 行を出し、ルーター経由が種別あたり 10 項目で宣言した `min_items` の 20 に届かないため `undetermined` になる。ルーター経由の窓で導き直しが動いた種別には `changed` 行が出る。ルーターのモデルファイルはコンテナが root で書くので、片付けはコンテナを通して消す。このブロックは 2026-11-08 にこのブランチに対して書いたとおりに実行した。その回では 2 種別が `gpt-6.1-terra` で `certified` になり、ルーターが起動し、40 件すべてが応答を返し、片付け後に何も残らなかった。
