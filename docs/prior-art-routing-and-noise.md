# What the literature already settled, what it confirms here, and the two things nobody has measured

Surveyed 2026-09-04 against arXiv. The question was not "has routing been studied" but the narrower one that
changes what is worth building next: **for each conclusion this project reached the expensive way, is there
published work that reached it first, and does that work agree?** A conclusion that is already published needs
no more GPU time here. A conclusion that contradicts published work needs the contradiction resolved before it
is acted on. A conclusion nobody has published is where the remaining measurement budget belongs.

## 1. 「学習ルータは静的割当を超えない」は独立に三度出ている (design 3b, 3c と results-router-on-a-cluster)

三本が別の角度から同じ壁に当たっている。

**"The Routing Plateau" (arXiv:2606.07587)** は 21 手法 × 5 ベンチで、設計がまったく違う手法どうしが「狭い性能帯に収束し、oracle からはるかに下」に並ぶことを報告する。原因を *predictability bottleneck* と名付け、ルータが学んでいるのは「モデル性能の全体平均の傾向」であって「問い単位の信号」ではないと述べる。だから簡単な問いでは重複して当たり、難しい問いでは揃って外す。

**"Most of the LLM Routing Gap Is Task Type" (arXiv:2608.23023)** はその含意を実験にした。14 モデル × 294 問 (7 タスク型 × 韓・英・ヒンディー) の行列を二度取り、両方で正解した時だけ正解と数える規則を置いた上で、ルーティングで改善できる問いが **29 問**しかないことを示す。うち **21 問はタスク型ごとに一つモデルを事前に割り当てるだけ**で取れ、言語で割ると 2 問増え、残りは 6 問。つまり学習ルータが取りに行く余地は 294 問中 6 問で、これは run 間のばらつきより小さい。採用した静的表は 294 問中 262 問を **$3.33/run**、単体最良は 245 問を **$7.69/run**。

**"Opportunity Is Not Realizability" (arXiv:2608.08265)** は上限と実現値を分けて統計を付けた。8 チェックポイント × 4 ベンチで oracle 差は **9.7-30.7 ポイント**あると選択補正済み区間で保証できるのに、最強の実運用可能なプロンプトルータが回収するのは **その 7.5-14.4% だけ**、そして 11 方策の最良に同時区間を張ると下限は全条件で 0 になる。

**ここへの含意。** 我々の `results-router-on-a-cluster.md` の結論 (incumbent のカテゴリ表が学習ルータ全部に勝つ) は再発見であって、もう検証の対象ではない。**残っている問いは「難易度でのルーティング」だけ**で、これは `noise-floor-reverses-specialisation` の結論と一致する。専門性 routing に予算を足す理由は文献側にもない。

`prefill-router-prize-is-four-cents` はこれをさらに一段先に進めている点だけ独自性がある。上の三本は「ルータが信号を学べない」と言うが、我々は agentic 側で **完璧な予測器でも取り分が 1 件 $0.0395、held-out で 0.0%** だと示した。信号ではなく経済で死ぬという主張は、文献の predictability bottleneck とは別の死因である。

## 2. run 間のばらつきは我々の環境の欠陥ではない (design 3d, 3e と results-box-run-to-run-noise)

`temperature=0` は決定的ではない。**arXiv:2506.09501** は greedy 復号でも精度に最大 9 ポイント、出力に 9,000 トークンの差が出るとし、原因を浮動小数の非結合性に置く。**arXiv:2608.14376 (CoRun)** はもっと具体的で、バッチ構成が変わるとカーネルのタイル分割と縮約順序が変わるためだと帰属させる。**arXiv:2601.19934** は T=0 でも非決定性が残り、モデル規模と提供形態でパターンが違うと報告し、**arXiv:2604.22411** は「background temperature」という呼び名を提案する。

上の 2608.23023 は同じ行列を二度取って **4,116 ペアの 5.37% が別の点数になった**と報告する。我々の pooled は **6.4%**、候補別には **0.9%-24.0%** で、桁は一致する。

**ここへの含意。** 二つ。第一に、`reproduce.compare` が要求している「二回取るまで frontier を方策として引用しない」という規則は、文献の数字にも支持されている。第二に、**arXiv:2606.06924 (DARS)** はこれを教師信号の側から攻めていて、単発の応答をモデルの能力ラベルに使うと系統的ノイズが入ると示し、入力側 (意味等価な言い換え) と出力側 (確率的生成) の両方から分布を作る。我々の repeat は出力側だけで、入力側は取っていない。**入力側を足すのは安く、`outcomes.Cell` の形を変えずにできる** — 同じ item に対する言い換えを別 item として測るのではなく、同じ item の追加サンプルとして畳む。これは実施候補として `p_next_bound` の事前分布を締める効果もある。

## 3. 我々の検定の形は、文献が指摘した欠陥の正しい側にいる (design 3e, reproduce.py)

2608.08265 の指摘は二点。**同じ例で「最良固定モデル」を選んでから同じ例で対検定すると、対推論が無効になる**。そして **全情報 oracle は実運用ルータが観測できない結果を見ている**。この論文は三つの推定量 (結果 oracle の機会、宣言済み事前信号からの Bayes 最適利得、学習ルータの held-out 利得) を分け、モデル選択後も有効な信頼区間を証明する。

我々の `reproduce.py` はこの一つ目を偶然回避している。`ordering` 主張を run 1 自身の厳密対符号検定に条件付けているのがそれで、`subset_integrity` の失敗を握り潰さないのも同じ理由に効く。ただし**二つ目は回避できていない**。`quorum.enumerate_policies` が方策空間を列挙して `cheapest_meeting` が最良を選ぶ構造は、まさに「ルータ族の最良メンバを選ぶ」形で、選択補正なしに区間を張ると狭すぎる。

**実施済み、そして予想より重かった。** `reproduce.simultaneous_wilson` と `select_at_floor` を足して測った結果が `docs/results-selection-cost.md` にある。571 問に対して**方策は 480 通り**あり、勝者の点推定と保証できる下限の差は **6.7 ポイント**、うち探索を払う分が **3.4 ポイント**。**5 つの床 × 2 run の 10 通りのうち 9 通りで、推薦は引用された床を満たさない。** 2608.08265 の「11 方策の最良の同時区間は下限 0」がこの規模でどう出るかの実測にあたる。

そして重要なのは、**この欠陥は繰り返しでは絶対に見つからなかった**という点である。9 件のうち 8 件は run 2 でも同じ方策が勝っている。3b・3d・3e はどれも「もう一度測る」で見つけた訂正だが、これは「他人が既に証明したことを読む」でしか見つからない種類の訂正だった。後者の方が安い。

## 4. 棄権の非対称性: 我々の AUC = 0.5000 は原理ではなく信号の選択だった (design 4c)

これが今回の調査で一番方向性を変える発見である。

`4c` は「カスケード自身の履歴 (どの tier が失敗したか) で『誰も解けない』を予測する」問題で AUC = 0.5000 という厳密な結果を出した。証明は、決定点で条件付ける集合が定数だから、というもので、それは正しい。しかしそれは **その信号では無理**という証明であって、**この予測が原理的に不可能**という証明ではない。

**arXiv:2607.08456 "Two Axes of LLM Abstention"** はそこを直接測っている。5 モデル (2B-14B、3 系統) で、「この答えは間違いか」と「この問いはそもそも答えられるか」は**別の軸**だと示す。通常の答えの自信度は正答性を追えるが、回答可能性にはほぼ盲目で、**その盲点は規模で縮まらない**。前提が偽の自然発生的な問い (CREPE) では、答えの自信度・P(IK)・P(True)・「前提は偽か」と直接聞くこと、すべてが偶然水準に留まる。ところが**隠れ状態への線形プローブは AUROC 0.69-0.77 に届く**。論文の言い方は "the model represents a problem it will not report" — モデルは問題を表現しているが報告しない。前提確認を指示すると逆効果で、健全な前提まで争い出す (誤った異議 57%)。プローブで同じ指示をルーティングすると異議の適合率がおよそ三倍になる。二軸方策は正答の被覆 **0.75** で両方の予算を保証し、単一閾値は **0.31**。14B では二軸だけが保証を出せる。

**ここへの含意。** 我々の 4c の結論「固定した打ち切り深さ (24.4% 節約、9.7% 損失) が唯一の選択肢」は、**利用できる信号の集合を出力側に限った場合の**結論だと書き直すべきである。文献が言っているのは、回答可能性の信号は出力側にはなく、隠れ状態にあるということ。そして我々の状況で決定的なのは:

- API 候補では隠れ状態は取れない。だから API のみのカスケードでは 4c の結論はそのまま生きる。
- **自前サービングの箱 (qwen3.6 / g6e.2x) では隠れ状態が取れる。** これは箱を持っていることの、これまで数えていなかった価値である。`box-cascade-moe-and-margin-judge` で回答トークンの logprob margin が AUC 0.838 に届いたのは、この方向の一番浅い版にあたる。margin は出力側だが、隠れ状態そのものではない。
- したがって **`4c` の後続として測るべきは「箱の隠れ状態プローブで『誰も解けない』を当てられるか」** で、これは我々の 51 件 (誰も解けない) 対 143 件 (高い tier が要る) の分離問題にそのまま当たる。文献の 0.69-0.77 は前提が偽の問いでの数字で、我々の「難しすぎる」問いでどうなるかは未知。

ただし注意点を一つ。2607.08456 の「回答可能性」は主に**前提が偽・答えが存在しない**問いであり、我々の 51 件は**答えは存在するが誰も届かない**問いである。同じ軸とは限らない。だからこれは仮説であって、置き換えではない。

## 5. 空白その一: 一致が最良単体を何ポイント上回るかを、誰も報告していない (design 2, quorum.py)

`quorum.Report.agreement_lift` を足したのは、「一致で止めた時の精度」を単独で報告すると意味がないからだった。最良メンバの全体精度より低い一致があり得る。文献を探した結果、**この量を報告した論文は見つからなかった**。

近いものは **arXiv:2608.03744** で、「二つの peer が同じ誤答を主張すると、試験中の holdout が **38%** の場合にそれを採用する」と報告する。これは我々の `joint_failure` に相当する側の測定で、共倒れの危険を測っている。しかし「一致した時に止めるという規則が、いちばん強い一人をそのまま使うのに比べて何ポイント得か」は測っていない。

**ここへの含意。** `quorum-stopping-rule-survives-arbitration-dead` の中身 (安い 3 つの一致が箱の迷いより良いエスカレーション信号で費用 -26%) は、文献に対して新規の主張である。ただし公開できる形にするには 2608.08265 の選択補正 (行 3) が先に必要で、順序はそちらが先。

## 6. 空白その二: 正解表の壊れを全候補一致で検出する

`unanimity-detects-broken-answer-keys` の内容 — 「全候補一致かつ全員不正解」で的中率 19/19・誤検出 0、8 候補一致に緩めると 3/9 に急落、請求の 54.8% を占める「誰も解けない」51 件のうち 22 件が壊れた問題 — に対応する先行研究は見つからなかった。ラベル誤りの一般論 (arXiv:2410.18889、arXiv:2502.03461) はあるが、MMLU 系での割合の定量も、全候補一致を検出器に使う話も出てこない。

**ここへの含意。** `docs/results-label-audit.md` と `abstain.broken_key_candidates` は、この projectの副産物のうち外に出す価値がいちばん高い部分かもしれない。ただし 22/51 という数字は 699 問の一つの fold から出ており、他ベンチに一般化する主張はしていない。

## この調査が主張しないこと

arXiv の API 検索とアブストラクトだけで、本文は読んでいない。だから「見つからなかった」は「存在しない」ではなく「この検索語では出てこなかった」である。行 5 と行 6 の空白の主張はその弱さを負っている。数字はすべて各論文のアブストラクトからの引用で、我々が再現したものではない。
