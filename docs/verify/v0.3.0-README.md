# v0.3.0's phase-5 verification: what was observed, and what was not

Two halves, because two questions need two kinds of evidence: whether each entry's defect is gone, and whether the
mechanism works against a real engine. The split is not a convenience — a check a cheaper harness can make belongs in
the cheaper harness, and a claim about live occupancy cannot be made anywhere else.

## Half one: reproduce and verify, per entry

`v0.3.0-pairs.json` holds nine pairs across six entries. Each observation was made **at the commit before that
entry's fix landed** and again at `HEAD` — not at the previous release, because for two of the six the observation
cannot be made at `v0.2.0` at all: `Policy` had no `validated` field there (C1 is the rename), and
`policy_digest` did not exist.

Every observation is of the cause the contract names. None is a downstream symptom several unrelated states could
also produce.

| entry | reproduce | verify |
|---|---|---|
| C1 | the same fabricated bound of **0.99** with `bound_kind` of `lcb`, `point_estimate` and `asserted_by_operator`: **all three admissible, interchangeable**. And a candidate whose bound is **0.10** against a floor of 0.80, under a validated policy: **`certified: true`** | the claim naming a correction nothing performed is refused as `unearned_correction`, so the three stop being interchangeable; the below-floor candidate is **`certified: false`** |
| C2 | no digest function, no digest field, and `--policy-version` defaulting to **`"unversioned"`** | a digest that is a function of the artifact's content (`d6fc094743afd124` for the fixture), and no default |
| C3 | a family declaring no `tenant_scope`: **accepted** | refused, naming the missing field |
| C4 | the verb is in neither `cli.py` nor `README.md`; running it exits **2** because no such verb exists | both, and the door exits **1**: `refused: 'r1' already carries the label False and this call says True` |
| C5 | `floor_ceiling` **absent** for both shipped families | ceiling **0.8609** on a cohort of **20**, needing **14** items for agentic-coding's 0.80 and **36** for retail's 0.92 |
| C6 | the shipped ledger compiles to zero rules, and the candidate set holds **1** member (`api-strong-a`) | **3** members |

C6's reproduce line is the previous release's own failure, isolated at its cause. Over 400 live decisions that
release's exploration draw returned `no_eligible_arm` every time and the diverted share was 0.0 against a declared
0.05 — because the set came from `policy.rules` and the compiled policy has none.

### One pair whose two sides agree, and why that is the finding

`C4 — a changed label, through the primitive` reads `append_accepted: true` on **both** sides. That is not a gap: the
door is a CLI-layer refusal, and `Log.attach_outcome` still accepts a contradicting label by design. The pair records
both layers on purpose, because "which layer holds the check" is a fact the artifact should carry rather than one a
reader has to infer. What changed at the primitive is the other half — `Log.read()` now reports the orphan outcome
(`{"count": 1, "request_ids": ["r1-typo"]}`) where before it returned it silently.

### Four defects in this harness, all of the same shape

Found while running it, and worth stating because every one of them made a pair look like evidence when it was not.

| # | what the harness did | how it looked |
|---|---|---|
| 1 | `ROOT` was a relative path and `cwd` was `ROOT/src`, so every ledger path resolved inside itself | both sides failed `compile` identically **except for the path in the message**, so the pair "differed" and proved nothing |
| 2 | C3's fixture had an empty `candidates` map | the base refused for *that* reason, never reaching the omission under test |
| 3 | C3's fixture then set `price_card`, a measurement-only key | refused again for an unrelated reason, both sides identical |
| 4 | C1's fixture had `rules=()`, so no rule fired and `route_once` returned the default | `certified` read `false` on both sides and distinguished nothing |

Defects 2 and 3 were fixed by lifting a candidate straight from the shipped config rather than hand-writing one, so
the fixture is config-legal by construction on both sides. Defect 4 by giving the policy a rule that fires.

The pattern is one pattern: **a pair whose sides agree because the observation never reached the thing under test
reads exactly like a pair whose sides agree because the defect was never there.** The harness now records
`unobservable_here` with the exception rather than letting an absent symbol read as an absent defect.

## Half two: the engine

See `v0.3.0-engine-verify.json`.

**Exploration's draw diverts on live traffic, and this is the first release in which that could be observed at
all.** The previous release recorded 400 consecutive draws returning `no_eligible_arm` and a diverted share of 0.0
against a declared 0.05.

| | previous release | this run |
|---|---|---|
| draws with an alternative available | **0 / 400** | **200 / 200** |
| traffic actually diverted | 0.0% | **10 of 200 = 5.0%**, against a declared 5% |
| candidates reached | 1 | **3** |
| distinct state readings | -- | **19**, so occupancy is a measurement rather than a constant |

The recorded run is the only one quoted. Earlier runs of the same task diverted 3.5% to 6.0%, and they are **not** in
the artifact because the harness was still wrong at the time -- a reused log summed two runs into `served: 400` on a
200-request run. A range a reader cannot check against the artifact is the kind of claim this release exists to stop,
so the artifact's own single run is the result and the spread is described here as what was seen while the harness
was being corrected rather than offered as a measurement.

**Every record names the artifact it came from.** All 200 decisions carry `policy_digest` `5eefad2fc8b6b8b8`, which
is the compiled artifact's own hash rather than anything a caller typed.

**`floor_is_reachable` returns a verdict from the recorded ceiling**: `pass`, "the declared floor 0.8000 does not
exceed 0.8609, the ceiling a 20-item cohort imposes".

**The door moves a criterion, and the criterion's overall verdict still stands -- for a reason worth stating.**
Before any outcome is attached, `floor_compliance` has nothing to compute. After 40 outcomes through the documented
verb, the served population reads 40 labelled decisions at a realised rate of 100% with a 95% lower bound of
**92.78%**, which clears the floor. The **overall** verdict remains `unsupported` because `certified` is **0** on
all 200 decisions: the shipped ledger compiles to `validated: false`, and amendment 6 made certification the
conjunction of validated rules and an admissible candidate. That is the conjunction working, not the door failing.

**`default_is_not_a_hiding_place` reports FAIL**, at a 100% uncertified share against a 10% tolerance, for the same
reason and by the same mechanism as in the previous release. It is reported here rather than tuned away.

**The documented path runs in order, and two non-zero exits are the documented behaviour.** `route` exits 2 on the
shipped policy because that policy is `provisional`, which `README.md` states, and exits 0 with
`--allow-unvalidated`. `observe` exits 3 because the state is incomplete on a first call -- an arrival rate needs a
previous counter reading -- and given the first observation the second produces one, moving
`arrival_rate_per_hour` from absent to 372871.4 per hour. Both are recorded so a reader can tell a refusal from a
fault.

### Eight defects in this harness, and they share one shape

Four in the hermetic half are tabled above. Four more in the engine half: three guessed signatures
(`observe`'s keywords, `route_once`'s `authorised`, `accept`'s non-existent `--family`), `--previous` handed the
readings rather than the observation file, stderr discarded so three non-zero exits could not be diagnosed, and a
log reused between runs so two runs summed into `served: 400` on a 200-request run.

Every one was answerable by reading the signature or the file first. And every one made an observation look like a
result: a wrong flag reads as a broken step, and a summed log reads as a bigger sample. Its subject is C6: whether exploration's draw diverts on live traffic, which needs
`observe` reading real occupancy and cannot be settled hermetically. The run's configuration, the instance and the
per-observation results are recorded there.

## What was NOT verified, and why

An honest gap is information. A gap presented as coverage is the failure this phase exists to prevent.

**The absolute bound is still supplied by a caller.** C1 makes the claim about a bound honest; it does not make the
bound a measurement. The contract's carried-forward obligation says so, and R1 records why computing it here was
rejected rather than deferred by accident.

**Retirement is absent.** A candidate that stops clearing keeps clearing until somebody recompiles and notices. Age
stands where a change point belongs.

**`tenant_scope` is recorded and not acted on.** C3's interface says so in its own words. Nothing here routes per
tenant, and the declaration exists so the cardinality is stated rather than assumed.
