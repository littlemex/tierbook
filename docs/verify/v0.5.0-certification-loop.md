# v0.5.0 verification: the certification loop on billed traffic and a live router

**The claim under test.** From graded observations alone, the certification plane derives a per-task-type assignment
with a held-out check; the assignment exports to a configuration vLLM Semantic Router 0.4.0 accepts and routes by;
traffic sent through that router comes back as observations; and `drift` then says whether the deployed assignment
still holds, what a re-derivation would change, and what needs measuring. The claim fails if any step needs a hand
edit between commands, or if the router does not route the way the policy says.

Everything below ran on 2026-11-08 with the commands in `examples/certification_loop/README.md`: arms through an
OpenAI-compatible gateway with real billing, vllm-sr 0.4.0 (`pip install vllm-sr==0.4.0`, image
`ghcr.io/vllm-project/semantic-router/vllm-sr:v0.4.0`) in Docker on a single host, listener and management API
published on loopback only, traffic driven from the same host.

## Setup

| | |
|---|---|
| task | MMLU-Pro multiple choice; task types `biology`, `history`, `math`, `law` (the router's own domain labels) |
| measurement items | 250 per task type, 1,000 in all, split by `hash(split_salt, item)` into selection and held-out halves |
| routed items | three further windows of 40 per task type, disjoint from the measurement items and from each other |
| arms | `qwen3-next-80b`, `nemotron-super-3-120b`, `claude-haiku-4-5`, `claude-sonnet-5`, `claude-opus-4-5`, `gpt-6.1-terra`, `gpt-5.6-terra` |
| prices | the gateway's per-MTok rates, from its rate table at the pinned commit |
| declarations | `examples/certification_loop/declarations.json`: alpha 0.05, `tierbook.bounds:wilson`, `holdout_fraction` 0.5, `unobserved_as: rejected`, `max_observation_age_days` 30, `held_out_correction: none`, `min_items` 20, floors biology 0.80, history 0.60, math 0.60, law 0.45 |
| export | `--listener-address 127.0.0.1` (the default), `--management-bind 0.0.0.0` (vllm-sr 0.4.0's container requires it; published on loopback), `--management-port 18080` |
| spend | about $14.54 for 9,480 calls, computed as tokens x the same rates (the gateway does not return per-request cost without `infra/patches/stratoclave/0001`) |

## What happened, in order

### 1. A 32-token output budget measured the budget, not the arms

The first measurement capped answers at 32 tokens. 729 of 2,000 attempts ended with `finish_reason: length`, and the
arms that reason before answering looked worst: `claude-opus-4-5` committed to an option letter in 117 of 400. The
observations now carry `finish_reason` and every cell reports `cut_off_attempts`, which is what made this visible
without reading answers. The run was repeated at 1,024 tokens; the 32-token run is not used below.

### 2. Policy v1 from five arms

| task type | assigned | held-out rate | held-out lower | items | spend per accepted |
|---|---|---|---|---|---|
| biology | claude-sonnet-5 | 0.907 | 0.844 | 129 | $0.001342 |
| history | qwen3-next-80b | 0.690 | 0.601 | 116 | $0.000069 |
| law | claude-sonnet-5 | 0.770 | 0.688 | 122 | $0.001916 |
| math | claude-sonnet-5 | 0.918 | 0.856 | 122 | $0.001875 |

On the 489 held-out items both arms were observed on, the policy spends $0.001371 per accepted task against $0.001628
for the single best arm (`claude-sonnet-5`), a ratio of 0.84. A derivation on the first 100 items per task type had left
biology and history `unconfirmed` (the floor inside the held-out interval); 150 more items per task type is what
certified them, and until then the export skipped both and said why.

### 3. The router rejected every Claude response

v1 exported, validated (`vllm-sr config validate`) and served. Routed traffic to `qwen3-next-80b` worked; every request
the router sent to a Claude arm came back `502 The selected model returned an invalid response`. The router's log
named the cause: `field "usage": unknown field "cache_read_input_tokens"`. The gateway's OpenAI-compatible surface
returns Anthropic-shaped cache keys for Claude models, and vllm-sr decodes upstream responses strictly. This is the
gateway's defect, carried as `infra/patches/stratoclave/0002`.

`drift` on that window reported it rather than going quiet: 135 attempts under `unattributed_attempts` (a router that
fails before naming the arm records none), and the Claude-assigned task types `undetermined` with 0 graded items.
That report did not exist before this run; a window of failures had read the same as an empty one.

### 4. Policy v2 from the arms the router can reach

The operator's response is a candidate file without the Claude arms until the patch lands (the arm set moved), plus a
measurement of two arms the drift report listed as `never observed`. Re-derived:

| task type | assigned | held-out lower | spend per accepted |
|---|---|---|---|
| biology | gpt-6.1-terra | 0.854 | $0.000419 |
| history | gpt-6.1-terra | 0.720 | $0.000768 |
| law | gpt-6.1-terra | 0.760 | $0.001313 |
| math | gpt-6.1-terra | 0.908 | $0.000403 |

Every task type went to one arm, so the policy is the single best arm (ratio 1.00). That is a legitimate output and
the derivation reports it as such. History moved off `qwen3-next-80b` because the routed window added 25 of its
answers (17 accepted) and its selection lower bound fell under the floor.

Routed through v2, 159 of 160 requests succeeded and every one reached `gpt-6.1-terra`. The router put 130 of 159 into
the decision for their own task type; the rest matched no decision and took the policy's fallback. `drift`: all four
assignments `confirmed` (38/40, 33/40, 28/39, 34/40), no re-derivation change.

### 5. A price change alone moved the policy

With `gpt-6.1-terra`'s rates tripled in the candidate file (a probe, not a quoted price) and nothing re-measured,
`drift` reported three re-derivation changes and named them:

| task type | v2 | v3 | v3 held-out lower | v3 spend per accepted |
|---|---|---|---|---|
| biology | gpt-6.1-terra | gpt-5.6-terra | 0.835 | $0.001069 |
| history | gpt-6.1-terra | gpt-5.6-terra | 0.673 | $0.001537 |
| law | gpt-6.1-terra | gpt-5.6-terra | 0.688 | $0.002985 |
| math | gpt-6.1-terra | gpt-6.1-terra | 0.892 | $0.001327 |

v3 spends $0.001662 per accepted task against $0.002110 for the single best arm at the new price (ratio 0.79, 508
common held-out items). Routed through v3: biology, history and law requests the router classified into their own
decision reached `gpt-5.6-terra`, math reached `gpt-6.1-terra`, and unclassified requests reached the fallback.
`drift`: law and math `confirmed`, biology and history `consistent` (the floor inside a 24- and 30-item window), two
attempts unattributed (`empty_output_item`: an empty answer the router refused to forward).

## Findings that changed the code

| finding | change |
|---|---|
| the exporter's provider shape (`defaults.default_model`, backend `type`) is refused by vllm-sr 0.4.0 and by `main` | `defaults.model`, backend `provider` |
| vllm-sr 0.4.0's Docker stack refuses a loopback management bind inside its container | `--management-bind` / `--management-port`; the default stays loopback, which that stack refuses, so this run passed `0.0.0.0` (the container side; the host publish stayed loopback) |
| the exporter's listener `address: 0.0.0.0` made the router publish its port on every host interface, in front of a backend holding a key | listener address is `--listener-address`, default `127.0.0.1`; in-cluster export passes `0.0.0.0` |
| `vllm-sr config apply` refused a tierbook config with `RESTART_REQUIRED: tracing configuration changed` | redeploys use `vllm-sr serve --replace-active-config`; recorded here, not worked around |
| answers cut off at the output budget were indistinguishable from wrong ones | `finish_reason` on observations, `cut_off_attempts` per cell |
| failed routed requests vanished from `drift` | `unattributed_attempts` |
| re-running a drive or an ingest appended and double-counted | both replace their output unless `--append` |
| the gateway's Claude responses carry non-canonical usage keys | `infra/patches/stratoclave/0002` |
| per-request cost and the billing rate are not readable by a caller | `infra/patches/stratoclave/0001` |

## What this does not show

* The held-out halves were looked at more than once: after 100 items per task type and again after 250, under the
  same `split_salt`, so the nominal 1 - alpha of the final check is optimistic. A fresh salt would have avoided it.
* The guarantee is per task type at 1 - alpha and conditional on the dataset's labels. Routed traffic is labelled by
  the router's classifier, which put 130 of 159 and 125 of 158 requests into their own task type's decision; the
  assignment's held-out bound says nothing about the requests the classifier sent elsewhere.
* The v3 price is a probe. What it shows is that the derivation responds to a price and to nothing else; it is not a
  claim about any vendor's pricing.
* Claude arms were not routed through vllm-sr. Their measurements are real; their routing waits on patch 0002.
* One host, one router replica, no self-hosted arm. A fixed-cost arm enters only through a declared `usd_per_attempt`.
